# 通用软件官网 — 产品需求文档（PRD）

> Owner: `master-relay`（主线）。任何任务分支不得编辑本文件。
> Status: **已评审并拆解为任务（v0.1）** — 开放问题在评审前按 §13 的「默认假设」执行；
> 任务见 `docs/tasks/`，接口契约见 `docs/api/frontend-api-contract.md`。

## 1. 概述

为本公司的通用软件产品建设一套「官网 + 用户中心 + 内容管理后台」：

- **官网（frontend/）**：多语言的营销与文档站点，包含首页、功能、文档、价格、关于、联系我们，以及登录/注册和用户控制台。
- **用户控制台**：注册用户可自助修改密码、查看积分余额与积分流水、维护基础资料。
- **后端与管理后台（backend/）**：复用现有 Go API 与 easy-admin 管理后台，新增站点内容管理能力，使**软件名称、品牌信息、各页面文案/内容、价格方案、文档、导航、联系方式等均可由后端配置**，前端不写死。

一句话：**一个可运营（内容可由后台管理）、可注册登录、中英双语、面向潜在客户与现有用户的软件官网。**

## 2. 问题与动机

- 目前只有 Nuxt 起始模板（未接后端、无 i18n）与 easy-admin 后端骨架，没有可对外发布的官网。
- 产品名称、定位、价格、文案会频繁调整；若硬编码在前端，每次改动都需要发版。
- 需要面向中英文用户，语言切换与内容本地化必须是一等公民，而非后期补丁。
- 已有用户体系与积分体系（后端已实现），但缺少面向用户的官网入口与控制台，用户无法自助改密或查看积分。

## 3. 目标

- **G1**：提供结构完整、可 SEO、多语言的营销官网，覆盖首页/功能/文档/价格/关于/联系。
- **G2**：官网所有面向运营的内容与品牌信息（含软件名称）可由管理后台维护，无需改前端代码即可上线。
- **G3**：打通后端业务用户体系，提供注册/登录/邮箱验证/找回密码与用户控制台（改密、积分查询、资料）。
- **G4**：至少支持英文与简体中文，语言可扩展；缺翻译时有回退而非空白。
- **G5**：可部署、可观测、性能与无障碍达到商用官网基线。

## 4. 非目标（本期不做）

- **在线支付 / 自助订阅 / 计费**：价格页仅展示方案并跳转注册或联系我们（❓ 见 Q2）。
- 博客/新闻中心、社区、工单系统（未来可另立 PRD）。
- 用户自助消耗积分、兑换、充值（积分仅展示；发放/调整仍由管理员操作）。
- OAuth/第三方登录（登录方式保持用户名 + 邮箱）。
- 移动 App、桌面端。
- 多租户、多站点（一个部署服务一个产品）。
- 与前端无关的后端内部重构。

## 5. 目标用户

| 角色 | 描述 | 核心诉求 |
| ---- | ---- | -------- |
| 访客 | 搜索引擎/链接进入，未登录 | 快速理解产品价值、看功能与价格、读文档、联系销售 |
| 潜在客户 | 正在评估 | 清晰的方案对比、试用/注册入口、可信的联系方式 |
| 现有用户 | 已注册 | 登录后改密码、查积分与流水、维护资料 |
| 内容运营 | 使用管理后台的非技术人员 | 维护文案、价格、文档、导航、联系方式，按语言编辑，预览后发布 |
| 管理员 | 现有 easy-admin 管理员 | 用户/积分/角色/审计管理（复用现有），审核联系表单 |

## 6. 现状与缺口

**已具备（复用，不重复建设）**

- 后端 Go API：管理员 RBAC + 审计（pending-first）、业务用户注册/登录/邮箱验证/刷新/登出、JWT + Redis 会话与撤销（`auth_epoch`）、积分余额与流水（`NUMERIC(20,4)`、幂等键、不可为负）、用户等级、系统设置单例（含 `platform_name`、`public_frontend_url`、`public_api_url`、注册开关、登录方式、邮箱验证开关、默认头像）、SMTP 加密配置与邮件发送。
- 管理后台 easy-admin：仪表盘、个人信息、系统设置、用户、用户等级、角色、管理员、审计。
- 前端：Nuxt 4 + Nuxt UI + Tailwind，仅起始模板。

**缺口（本 PRD 要覆盖）**

1. 前端无 i18n，无任何业务页面，未接后端。
2. 后端无站点内容模型（品牌/页面/功能/价格/文档/导航/联系表单）。
3. 业务用户接口缺：改密、资料更新、积分流水查询、忘记/重置密码；`/api/v1/me` 目前仅 `GET`。
4. 管理后台无内容管理相关界面。
5. 前端缺少登录态、控制台路由、SEO/站点地图、SSR 数据获取与缓存策略。

## 8. 功能需求

优先级：P0 必须本期完成；P1 本期尽量完成；P2 可选/后续。

### 8.1 国际化（FR-I18N）

- **FR-I18N-01（P0）** 支持 `en` 与 `zh-CN`；语言列表由后端配置（至少可增删启用语言，默认语言可配）。
- **FR-I18N-02（P0）** URL 策略：默认语言无前缀，其他语言加前缀（如 `/zh/...`）；配置项可切换为「全部带前缀」。`hreflang` 与 canonical 正确输出。
- **FR-I18N-03（P0）** 首次访问按 `Accept-Language` 重定向，用户手动切换后写入 cookie 并优先于浏览器语言。
- **FR-I18N-04（P0）** 语言切换器在头部与移动端菜单可用，切换后停留在当前页面。
- **FR-I18N-05（P0）** 界面固定文案放前端语言包；可运营内容（页面/功能/价格/文档等）的翻译存后端，按 locale 管理。
- **FR-I18N-06（P0）** 缺翻译时回退到默认语言内容，页面不得出现空白或错误；回退行为可观测（记录）。
- **FR-I18N-07（P1）** 日期/数字/货币按 locale 格式化；积分固定 4 位小数展示规则与后端契约一致。
- **FR-I18N-08（P0）** 严格禁止硬编码面向用户的字符串；CI 检查语言包 key 覆盖率与未使用 key。
- **FR-I18N-09（P1）** SEO：`<html lang>`、按 locale 的 sitemap、`x-default`、按 locale 的 `<title>`/description/OG。

### 8.2 官网前端（FR-FE）

站点信息（软件名称、Logo、标语、页脚、导航、SEO 默认值、社交/备案信息）来自后端公开设置接口；接口不可用时使用内置兜底，页面可降级渲染。

- **FR-FE-01（P0）** 全局布局：响应式头部（Logo/导航/语言切换/登录注册入口）、页脚（链接、版权、备案）、404/500。
- **FR-FE-02（P0） 首页**：Hero（标题/副标题/主次 CTA/背景图）、核心功能亮点、产品截图/演示、价格/CTA 区块、信任背书（可选）。内容均可后台配置。
- **FR-FE-03（P0） 功能页**：分组功能卡片（图标、标题、描述、配图），支持后台增删改与排序；可选详细区块。
- **FR-FE-04（P0） 文档页**：分类 + 文章树，Markdown 内容，文章内 TOC、上一篇/下一篇、按 locale 展示；支持草稿不对外。
- **FR-FE-05（P0） 价格页**：方案卡（名称、描述、价格、周期、币种、功能清单、是否推荐、CTA），支持月付/年付切换；CTA 指向注册或联系。价格只展示，不支付。
- **FR-FE-06（P0） 关于页**：富文本/Markdown 内容（公司介绍、使命、里程碑/团队可选），可后台配置。
- **FR-FE-07（P0） 联系我们**：联系方式（邮箱/电话/地址/地图可选）+ 表单（姓名、邮箱、公司可选、留言、隐私同意）；提交后落库并提示成功，触发管理员通知邮件。
- **FR-FE-08（P0） 注册/登录/邮箱验证/找回密码**页面：与后端 `auth` 接口对接；表单校验、错误提示双语、限流错误友好提示。
- **FR-FE-09（P0） 登录态**：access token 仅存内存，刷新令牌走 HttpOnly cookie；页面刷新可静默 `refresh` 恢复登录态；跨标签页基本一致。
- **FR-FE-10（P0） 用户控制台**：需登录，路由 `/account` 下：
  - 概览：昵称/头像/邮箱/注册时间、等级、积分余额。
  - 安全：修改密码（当前密码 + 新密码 + 确认）。
  - 积分：余额、累计消耗、当前等级、流水列表（分页、时间/原因/变动/结果余额）。
  - 资料（P1）：昵称、头像 URL（❓ 邮箱改绑见 Q5）。
- **FR-FE-11（P0）** 受保护路由未登录时跳转登录并回跳原地址；401/403/网络错误有统一处理。
- **FR-FE-12（P1）** 加载/空态/错误态组件统一；骨架屏用于异步内容。
- **FR-FE-13（P1）** 公开页面 SSR/预渲染 + 内容缓存与后台发布后重验证，保证首屏与 SEO。
- **FR-FE-14（P2）** 文档全文搜索（❓ 见 Q4）。
- **FR-FE-15（P1）** 无障碍：语义化标签、键盘可达、焦点可见、对比度达标、`alt` 文案。

### 8.3 用户认证与控制台后端缺口（FR-API）

- **FR-API-01（P0）** `GET /api/v1/me` 扩展返回：积分余额、累计消耗、等级信息、注册时间（沿用现有 4 位小数字符串契约）。
- **FR-API-02（P0）** `POST /api/v1/me/password`：当前密码校验 + 新密码（8–72 字节），成功后撤销该用户会话并要求重新登录（❓ Q6），写入审计。
- **FR-API-03（P0）** `GET /api/v1/me/point-transactions`：仅本人流水分页查询（时间倒序，可选时间范围），不暴露他人数据。
- **FR-API-04（P1）** `PATCH /api/v1/me`：昵称、头像 URL。
- **FR-API-05（P1）** `POST /api/v1/auth/forgot-password` + `POST /api/v1/auth/reset-password`：复用一次性 token + SMTP 基础设施，限流、不泄露账号是否存在、单次有效；重置后 bump `auth_epoch`。
- **FR-API-06（P0）** 所有用户侧接口沿用现有安全基线：JWT + Redis 会话、`auth_epoch` 校验、失败关闭、限流、统一错误码、审计（涉及安全事件的写入）。

### 8.4 站点内容管理后端（FR-CMS）

所有内容均为「实体 + 多语言翻译 + 发布状态」，公开接口只返回已发布内容；管理写入走现有权限与 pending-first 审计。

- **FR-CMS-01（P0） 品牌与站点设置**：软件名称、Logo、favicon、标语、默认 SEO（title/description/OG 图）、社交链接、联系邮箱/电话/地址、版权、备案号、分析工具 ID（可选）。扩展现有 `system_settings` 或新增站点设置单例（❓ Q1）。
- **FR-CMS-02（P0） 导航与页脚**：可配置菜单项（标签、链接、排序、是否新窗口、可见性、父级可选），按 locale。
- **FR-CMS-03（P0） 首页区块**：Hero 文案与 CTA、功能亮点引用、截图/演示、底部 CTA 等，按 locale，可排序。
- **FR-CMS-04（P0） 功能条目**：图标、标题、摘要、详情、配图、分组、排序、发布状态，按 locale。
- **FR-CMS-05（P0） 价格方案**：名称、描述、月付/年付价格、币种、功能清单（逐条）、是否推荐、CTA 文案/链接、排序、可见性，按 locale。
- **FR-CMS-06（P0） 独立页面（关于等）**：slug + 标题 + Markdown 正文 + SEO，按 locale，发布状态。
- **FR-CMS-07（P0） 文档中心**：文档分类与文章（slug、标题、Markdown、排序、发布状态、SEO），按 locale；支持草稿/发布。
- **FR-CMS-08（P0） 联系表单收件箱**：存储姓名/邮箱/公司/留言/来源 IP/UA/语言/时间/状态（新/已读/已处理）；管理后台可列表、查看、改状态；可选邮件通知管理员。
- **FR-CMS-09（P0） 公开内容接口**：提供颗粒化只读接口（站点设置、导航、页面、功能、价格、文档分类/文章）与缓存头；仅返回启用/已发布内容，字段白名单。
- **FR-CMS-10（P0） 输入安全**：Markdown 服务端净化、URL 白名单、图片类型/大小限制；管理接口只接受已鉴权管理员。
- **FR-CMS-11（P1） 草稿预览与发布**：预览 token 可查看未发布内容；发布后触发前端缓存重验证。
- **FR-CMS-12（P1） 内容排序与批量操作**：拖拽排序、批量显示/隐藏。
- **FR-CMS-13（P2） 定时发布、版本历史/回滚**。
- **FR-CMS-14（P0） 媒体**：图片上传（Logo、配图）与 URL 管理（❓ Q8 存储位置）。

### 8.5 管理后台界面（FR-ADMIN，`backend/server/admin/`）

- **FR-ADMIN-01（P0）** 新增「内容管理」菜单：站点设置、导航、首页、功能、价格、页面、文档、媒体。
- **FR-ADMIN-02（P0）** 新增「联系表单」收件箱页面（列表、筛选、详情、状态流转）。
- **FR-ADMIN-03（P0）** 内容编辑表单支持按语言分 Tab 编辑，缺翻译有显式提示；保存/发布权限复用现有 RBAC。
- **FR-ADMIN-04（P1）** 用户管理页展示并复用现有积分调整、等级、启用/禁用能力（已存在，仅确认入口可用）。
- **FR-ADMIN-05（P0）** 所有内容写入产生审计记录，符合现有 pending-first 协议。

## 10. 非功能需求

- **性能**：公开页面 SSR/预渲染；p75 LCP < 2.5s、CLS < 0.1、INP < 200ms（移动端 4G）；内容接口 p95 < 200ms。
- **SEO**：每页可配置 title/description/OG；sitemap.xml 按 locale；`hreflang`；结构化数据（Organization、Product、FAQ，视内容）；语义化 URL。
- **安全**：沿用现有认证/会话/限流基线；前端不落 access token 到 localStorage；HttpOnly + SameSite 刷新 cookie；CSP 与安全响应头；Markdown/HTML 净化防 XSS；管理写入审计；SMTP 密钥不泄露。
- **无障碍**：WCAG 2.1 AA 目标；键盘可操作；对比度与焦点可见；图片 `alt`；表单标签与错误关联。
- **兼容性**：最近两个大版本 Chrome/Edge/Safari/Firefox + iOS/Android 主流浏览器；≥360px 宽度可用。
- **可维护性**：前后端类型/契约与 `backend/server/docs/openapi.yaml` 同步；内容接口改动必须更新 OpenAPI。
- **可观测性**：接口结构化日志与请求 ID（已有）；内容接口错误率、联系表单提交量、邮件发送失败可监控。
- **合规**：联系表单收集个人信息需隐私同意与用途说明；提供隐私政策/服务条款页面（可用 FR-CMS-06 承载）。
